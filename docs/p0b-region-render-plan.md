## 一、为什么不是「按审计文档原样做 DECSTBM 滚动区」

审计里 P0-B 写的是「DECSTBM 把屏幕切成内容区 + 固定输入区」。读完全部渲染代码后，我认为直接上
滚动区不是最优解，理由三条（都是实测/代码可验证的）：

1. **滚动区内的输出不进 scrollback**。xterm 系终端在 DECSTBM 滚动区顶部滚动时，滚出的行是丢弃，
   不推入回滚缓冲。结果是用户拿不到"往上翻看历史输出"的能力——现在至少还能靠 /pause 停下复制。
   用滚动区等于用"输入框可见"换掉"输出可回滚"，这是等价交换，不是纯改进。
2. **内容区会被压缩到 rows-5 行**。24 行窗口下只剩 19 行内容区，任何稍长的回答都变成高频滚屏，
   视觉上比现在更抖。
3. **banner 4 行常驻 + 固定输入区 2 行，占掉 6 行**。小窗口（20 行以下）几乎没内容空间。

## 二、采用方案：追加式内容 + 底部固定输入栏

核心模型改成两段（这是 ink / Claude Code 这类 CLI 的实际做法）：

```
  ┌─────────────────────────────┐
  │  已提交内容（追加打印）        │  ← 普通 stdout 输出，自然滚进 scrollback
  │  ……                          │     可回滚、可鼠标选中复制
  ├─────────────────────────────┤
  │ 🔥 flare> 输入区（贴底，永远可见）│  ← 每帧原地擦除重绘，最多 N 行（折行）
  └─────────────────────────────┘
```

三条不变量：

- **I1 内容只追加，不重绘**。回答/工具输出/命令结果一旦写屏就不再擦除 → 进 scrollback。
- **I2 输入区永远贴屏幕底部**。内容变长靠屏幕整体上滚，输入区不移动、不消失。
- **I3 除启动外不再发 `\x1b[2J`**。全屏清屏是"输出放大 730 倍"和"输入框跑出屏幕"的共同根因。

## 三、渲染算法

状态：`lastInputRows`（上一帧输入区占的行数）、`inputDirty`（脏标记）、`contentQueue`（待追加内容）。

### 重绘输入区（唯一的高频操作）

```
1. 若 lastInputRows > 0：\x1b[{lastInputRows-1}A   光标上移到输入区首行
2. \r\x1b[0J                                     回到行首、擦到屏幕末尾
3. 写新输入行（prompt 呼吸色 + buffer）
4. lastInputRows = ceil(显示宽度 / cols)
5. 光标按 cursor 偏移绝对定位到输入区内
```

输入区只在 `inputDirty` 或火焰色步进时重绘，且**只重绘这几行**，与内容长度无关。

### 追加内容

```
1. 先擦掉输入区（同上 1-2 步）
2. 内容行按普通 println 写入（不定位、不清屏）→ 屏幕自然上滚，旧行进 scrollback
3. 重画输入区（lastInputRows 可能变）
```

流式回答时，pendingText 每帧更新 → 用"擦掉上一次写的草稿区 → 重写草稿区 → 重画输入区"，
草稿区行数有上限（比如 12 行），超出的部分定稿为已提交内容。

### 节流

- 输入变更：`onChange` 只置 `inputDirty = true`，实际重绘合并到 16 ms tick（粘贴 6000 字符 = 至多
  每分钟 3750 次 → 实际每 16 ms 一次，输出量与输入量解耦）
- 火焰呼吸色：仍按 80 ms 步进，但只改输入行 prompt 颜色（重绘输入区 1-N 行）

### SIGWINCH

`process.on('SIGWINCH')` → 重读 `columns/rows` → 重算 `lastInputRows` → 重绘输入区。
内容区不需要重绘（已经在 scrollback 里，终端自己会重排）。

## 四、待决策点（3 个）

### D1 火焰 banner 怎么办 —— 视觉变更，必须用户定

- **D1-a（推荐）静态开场**：启动时打印一次完整彩色 banner（进 scrollback，永久可见可回滚），
  之后动画只体现在输入行 prompt 的呼吸色（`flameBreathColor` 已有）。屏幕干净、零闪烁、可回滚。
- **D1-b 空闲时动画**：内容为空且空闲时保留 4 行跳动 banner，一旦有输出永久收起为静态。
  折中，但"突然收起"有跳变感，实现复杂度 +30%。
- **D1-c 保留常驻 banner**：banner 固定在顶部，必须回到 DECSTBM 滚动区方案 → 吃掉第二节说的
  三个缺点（不可回滚 + 内容区压缩 + 小窗挤爆）。

### D2 草稿区上限

流式回答时草稿最多占多少行？建议 12 行，超过的行定稿为已提交内容（不再变动）。
优点：屏幕不抖、长回答自然进 scrollback。缺点：极长回答时"最后 12 行"会随内容滚动。

### D3 /pause 的定位

重构后输入区本来就贴底不闪烁，`/pause`（冻结屏幕便于复制）价值下降。建议保留命令但标注为
兼容保留（行为变成：停止火焰呼吸重绘），不删——避免破坏肌肉记忆和脚本。
